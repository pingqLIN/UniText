# docs/

> Repository landing page for supporting documentation under `docs/`.

`docs/` collects long-form references, review packets, adapter notes, and design/architecture context that support, but do not replace, root governance documents.

## What belongs in `docs/`

Use `docs/` for:

- adapter-specific compatibility notes
- architecture and design references
- review-facing packets and supporting background material
- project-map references and visualization support files
- long-form notes that are not root policy definitions

If a file defines repo-wide policy, publication boundaries, delivery rules, or placement rules, keep it at repository root.

## Folder map

| Folder | Purpose |
|---|---|
| `adapters/` | host-specific compatibility and delivery notes |
| `architecture/` | architecture support material |
| `concepts/` | concept papers and explanatory notes |
| `design/` | design references and mockups |
| `operations/` | longer operational support docs |
| `plans/` | scoped planning materials |
| `project-map/` | project-map references and UI support docs |
| `reviews/` | review packages, shortlists, and review-facing materials |
| `working-notes/` | long-form supporting notes that are not root policy files |

## Boundary note

`docs/` supports the governance system and should not replace root files.

```text
Repository root policy docs:
- ../README.md
- ../INDEX.md
- ../OPERATIONS.md
- ../DOCUMENT_PLACEMENT_POLICY.md
- ../NO_PUBLISH_POLICY.md
```
