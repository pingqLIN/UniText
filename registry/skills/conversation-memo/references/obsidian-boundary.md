# Obsidian Boundary

Obsidian can be useful as an index layer, memo layer, or later integration target, but it should not automatically replace the raw archive and memo pipeline.

## Default rule

Unless the user explicitly asks for Obsidian output and provides a known vault target, do not write to the vault.

## Preferred default architecture

- raw archive layer
- memo layer
- formal layer
- optional Obsidian index / adapter layer

## Why this boundary exists

If Obsidian is allowed to become the default write target too early, these problems appear:

- raw discussion and memo notes get mixed together
- vault structure becomes part of the core workflow before it is stable
- formal documents and working notes become harder to distinguish
- direct vault writes can outpace document-placement or publishability rules

## When Obsidian can be activated

Obsidian integration is reasonable only when these are explicit:

- the target vault is known
- the write boundary is approved
- note type and destination are specified
- the memo lifecycle remains traceable back to the raw archive

## Recommended current posture

Treat Obsidian as a downstream adapter and indexing surface until the memo workflow is stable enough to make vault writes predictable.
