# Formalization Patterns

After a discussion memo exists, formal outputs may take one of several shapes.

## Pattern A: single reference or index file

Use when one document can safely hold the stabilized guidance.

Examples:

- one architecture note
- one policy note
- one index or control-layering file

## Pattern B: distributed references

Use when the discussion should be normalized into several documents.

Examples:

- one policy update
- one README adjustment
- one workflow appendix

## Pattern C: direct code realization

Use when the discussion results in executable behavior rather than a document-first outcome.

Examples:

- script change
- validator change
- telemetry field addition
- repo automation change

## Practical rule

Do not force a memo directly into one formal artifact shape unless the user asks or the project context makes the target obvious.

If multiple formalization paths are plausible, list them and let the next execution step choose.
